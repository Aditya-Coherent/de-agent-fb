- There are few large outliers

- MAE and RMSE : it tells absolute size of the error
- median absolute percentage error(sMAPE)
- R square
- bias : check model is systemically over or under fitting

Good to go : 
MRE < 5% or sMAPE < 5%
RMSE and MAE are reasonable
R² > 0.95
bias is near zero

2. SUPPLY-SIDE / BOTTOM-UP -- two techniques now, merged under supply/
------------------------------------------------------------------------
"Bottom-up" and "supply-side" are the same thing -- bottom-up is the
technique (sum real data upward), supply-side is the resulting number.
bottomup/ package fully merged into supply/ (no more separate pipeline).

  A) Company-based (src/me_engine/supply/) -- estimator.py, graph.py,
     financials.py, geography.py, discovery.py, verify.py
     - Real grounding: yfinance + InsightSentry (RapidAPI) fetch REAL
       filed revenue for PUBLIC companies -> hard-caps the LLM's guess.
     - For PRIVATE companies (no financial data anywhere): LLM still
       guesses from web snippets (ddgs), no real ceiling.
     - Real finding: for avocado oil (0/40 companies had financial data,
       all private) -- same --discover command run twice gave 318.6M
       then 737.0M then 585.4M -- 2x+ swing, confirmed unreliable when
       market has no public-company coverage.
     - Kept as OPT-IN (--method company), not default, because of this.

  B) Evidence-based (src/me_engine/supply/evidence_estimator.py) -- NEW,
     fully LLM-free, now the DEFAULT method.
     Steps: ddgs web search -> embedding relevance filter (sentence-
     transformers, same as Neon semantic search) -> regex number
     extraction (no LLM) -> Google Trends CAGR nudge (replaces the
     "sentiment analysis" idea from mentor's plan -- podcasts and Reddit
     were both tested and ruled out as free sentiment sources) ->
     median aggregation.
     - Verified working on avocado oil across 3 separate runs: 637-686M,
       consistent, ~8-15% error vs demand-side's 748.3M.
     - Real bug found + fixed: on "Global Smartphone Market" and later
       "Global Cloud Computing Market", low citation-extraction yield
       (only 3/15, then 4/12 snippets yielding a real number) produced
       a confidently-wrong total 2-7x too low vs real published figures.
       Fixed by raising the quality-flag thresholds (see section 3).
